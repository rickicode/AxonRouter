# AGENTS.md — AxonRouter Coding & Operational Guidelines

This document provides mandatory guidance for AI agents and developers working on AxonRouter.

## What this is

AxonRouter (`axonrouter`) — enterprise-grade AI routing gateway + Next.js dashboard. It exposes an OpenAI-compatible endpoint (`/v1/*`) and routes traffic across 40+ upstream providers with format translation, model-combo fallback, multi-account rotation, credential management, token refresh, and monthly partitioned usage tracking.

Published artifacts and layout:
- **Web Dashboard & Gateway**: Root Next.js standalone app (`src/`, `custom-server.js` on port `3777`).
- **Dedicated Hono API Gateway**: High-throughput Node cluster (`gateway/` on port `3778`).
- **Routing Engine**: Agnostic translation & execution pipeline (`open-sse/`).
- **Test Suite**: Vitest and Node test suites (`tests/`).

## Stack & Architecture

- **Runtime**: Node.js 22+ (ES modules only, no CommonJS `require`), Next.js 15 App Router (`--webpack`).
- **Primary Database (SSOT)**: Pure PostgreSQL 17 via `postgres` package (`src/lib/db/driver.js`, `src/lib/db/adapters/postgresAdapter.js`).
  - SQLite runtime is completely removed from application storage.
  - `src/lib/localDb.js` is a backward-compatible shim re-exporting from `@/lib/db/index.js`.
  - Partitioning: Native monthly range partitioning on `usage_history` and `request_details` (`src/lib/db/schema.pg.js`).
- **Speed Layer & Cooldowns**: High-performance in-memory TTL Map (`src/lib/cache/memoryStore.js`, `src/lib/cache/client.js`) for account/model cooldowns, circuit breakers, and rotation mutexes. Zero DB queries on hot path.
- **Context Optimization**: Optional Headroom compression sidecar.

- Production Start: `npm start` (port 3777)

## Mandatory Code Navigation (Graft)

A `graft/` context graph is maintained at repository root. Code search MUST prioritize graft over raw search:
1. Locate symbols / context: `graft ask "<query>"`
2. Regex / pattern search: `graft grep "<pattern>"`
3. Blast radius & callers: `graft callers <symbol>`
4. File API signatures: `graft skeleton <file>`
5. Synchronize graph after structural edits: `graft build`

## Coding Rules & Conventions

1. **Module System & Style**:
   - Plain JavaScript with ES Modules (`import`/`export`). No TypeScript.
   - Use path aliases: `@/*` maps to `src/*` and `open-sse/*` maps to `open-sse/*`.
   - Conventional Commits for commit messages (`feat(...)`, `fix(...)`, `chore(...)`).

2. **Database & Repositories**:
   - Never write raw queries in API routes. All database queries must live in repository modules (`src/lib/db/repos/*`).
   - Field synchronization: whenever `disabledAt` is updated on a provider connection, `is_active` must be updated synchronously to avoid false 503 states.

3. **Routing & Translation Pipeline (`open-sse/`)**:
   - Respect architectural boundaries: `src/sse/` is application glue; `open-sse/` is the agnostic routing engine.
   - All format pivots route through OpenAI format unless a direct pair translator exists (e.g. `claude:kiro`).
   - Translators must self-register with `register(from, to, reqFn, resFn)` and be imported in `open-sse/translator/index.js`.
   - Never hardcode role, model, or content-block strings; use constants in `open-sse/config/` and schemas in `open-sse/translator/schema/`.
   - Never edit `open-sse/providers/registry/index.js` directly; it is auto-generated by scripts.

4. **Error Handling & Account Cooldown**:
   - Client-side 4xx errors (400, 404, 413, 499) must NEVER trigger provider account cooldown or lockout. Client aborts (499) must be ignored in `markAccountUnavailable`.
   - Return structured error codes (`ACCOUNT_EXHAUSTED`, `MIXED_BLOCKED`) with `status_breakdown` and `retry_after` rather than ambiguous "No active credentials".
   - Upstream quota resets: precise `resetsAtMs` timestamps parsed from headers or body always take precedence over static rule cooldowns.
   - For `opencode-zen`, billing and entitlement errors are model-scoped (`opencodeZenModelOnlyError`); only explicit invalid API keys lock the account.

5. **Security & Deployment**:
   - `custom-server.js` enforces socket IP validation and strips untrusted `X-Forwarded-For` headers from non-loopback proxies.
   - Never commit `.env` or sensitive credentials (`DATABASE_URL`, `JWT_SECRET`, `API_KEY_SECRET`, `ENCRYPTION_KEY`).
